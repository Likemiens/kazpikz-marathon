# Android: паспорт, USB, kiosk, установка

Этот документ — инженерная инструкция по предлагаемой реализации, не данные
производителя конкретной панели. Фактические значения заполнить в
[device-profile.template.json](../specs/device-profile.template.json).

## Что запросить у поставщика одним сообщением

«Пришлите, пожалуйста, модель панели, фото “Об устройстве” с версией Android,
разрешение и ориентацию экрана. Нужен короткий тест: флешка появляется в системном
окне “Сохранить файл”, на неё можно записать файл и открыть на другом компьютере?
Когда можно поставить тестовый APK? Есть ли настройка kiosk/автозапуска?»

Разработчик при тесте дополнительно фиксирует API/ABI/RAM/free space, версию
WebView, raw pixels, density и фактический CSS viewport, доступ к DocumentsUI,
файловую систему флешки и поддерживаемый способ установки. Фраза «55″ Android»
не заменяет этот паспорт. Не менять системную прошивку самостоятельно.

## T00: ранняя проверка платформы

Установить подписанную тестовую сборку по разрешённой процедуре (первичная
debug-сборка допустима только для разработки). Закрыть сеть до запуска, открыть
экран с локальным KV/лого/казахскими буквами. Сохранить synthetic запись, закрыть
приложение, снова открыть и проверить count/ID. Создать тестовый ZIP, сохранить
на USB через SAF, прочитать обратно и сверить hash; открыть на ноутбуке.

Зафиксировать попытку сохранения при отключённом USB и отмене диалога. Проверить,
что из-за fullscreen/lock task системный picker не заблокирован. При недоступном
picker согласовать настройку поставщика до продолжения. Не обещать «любой USB».

## Выгрузка: один архив вместо пяти системных диалогов

Менеджер авторизуется → «Выгрузить сообщения» → приложение готовит ZIP →
стандартное Android «Сохранить» → менеджер выбирает флешку → «Сохранено и проверено».
В ZIP: all.xlsx, 10km.xlsx, 21km.xlsx, 42km.xlsx, moderation.xlsx и manifest.
SQLite backup отдельным действием и отдельным архивом; не смешивать его с
контентной таблицей. Короткая памятка внутри export напоминает про телефоны.

SAF обращается к URI, а не к известной букве диска. Полученный URI не доказывает,
что это USB: менеджер выбирает только физический локальный носитель. Облачные
провайдеры не использовать. Разрешения общего доступа MANAGE_EXTERNAL_STORAGE
и обходы scoped storage не нужны для выбранного интерактивного SAF-пути.

Fallback при несовместимом USB-provider — согласованный экспорт во внутренний
Documents/Downloads через системный picker, затем ручное копирование штатным
файловым менеджером на USB с проверкой на ноутбуке. Это **не автоматический
fallback релиза**: его надо испытать, описать и принять организатором. До этого
GATE-USB остаётся закрытым. Нельзя вместо USB внезапно предложить интернет.

## Полноэкранный режим не равен kiosk-блокировке

В приложении скрыть системные панели там, где API поддерживает; обрабатывать
Back в пределах UX, предотвратить сон на переднем плане. Это не блокирует все
аппаратные клавиши/Home/Recent. Screen pinning может требовать действий менеджера.
Полный lock task обычно настраивает поставщик/администратор устройства; права
device owner не подтверждены. Не включать DPC/MDM разработку в 60k молча.

Отдельный тест: вход оператором → открытие SAF под kiosk → возврат → повторная
блокировка. Если для picker надо временно выйти из kiosk, это только действие
менеджера; посетитель не получает обход.

## Установка и обновление

Release signed APK с checksum, версией, стабильным applicationId и ключом.
Поставщик разрешает установку из указанного источника. Не менять неизвестные
системные разрешения целиком и не оставлять USB debugging включённым без нужды.
Google Play аккаунт, сеть и загрузка assets на панели не должны требоваться.

Перед обновлением сделать внешнюю проверенную копию. Испытать установку APK
с большим versionCode поверх тестовой версии тем же ключом, сохранить device_id
и записи. При signature/version conflict **не удалять приложение** ради установки.
Остановиться и проверить версию/ключ/backup. Автообновление на Expo выключено.

Удалённая помощь возможна заранее при наличии связи. В полностью офлайн-дни
менеджер работает по инструкции; APK переносится флешкой, remote access не обещаем.

## Условия запуска

Поддерживаемый Android/WebView; APK загружается холодно офлайн; запись/retry/restart;
USB/backup/read-back; все клавиатуры; viewport/физическая доступность; kiosk+picker;
отключённые cloud backups; обновление без потери базы; оператор прошёл сценарий.
Неиспытанное остаётся NOT RUN, а не «должно работать».
