# Данные, Excel и модерация

Основания: SRC-01 / SRC-03. Конкретный файловый контракт — Inferred, выбран для однозначной реализации.

## Источники истины

SQLite хранит исходную запись. Не редактируем имя, пожелание и телефон через пользовательский интерфейс и не удаляем базу. Каждый экспорт — снимок, а не новая база.

Excel хранит ручные статусы после выгрузки. В SQLite нет авторитетного статуса «одобрено», потому что обратная синхронизация не входит. Не делать разрозненные редактируемые копии одного статуса на нескольких листах.

## Поля

`message_id` UUID; `device_id` стабильный ID инсталляции; `language` kk/ru/en; `distance_km` 10/21/42; `runner_name`; `wish_text`; `phone_raw`; `phone_normalized`; `created_at_utc`; `local_timezone`; `selected_phrase_id` или null; `template_modified`; `filter_status`; `filter_rule_ids_json`; `filter_version`; `app_version`; `payload_hash`; согласованные метаданные уведомления при их наличии.

`created_at_utc` создаёт native Kotlin по часам устройства. Для менеджера показывать локальное время с зоной, а в файлах сохранять и UTC-строку. До Expo проверить часы вручную: офлайн-приложение не получает достоверное время из интернета.

Телефон — строка с ведущим плюсом, без уникального ограничения. Одному номеру разрешены несколько пожеланий. Имя и телефон не используются для склейки записей.

## Словарная проверка

Проверять имя и текст по всем согласованным языковым спискам, а не только по языку интерфейса. Нормализовать Unicode и регистр для поиска, но сохранять оригинал. Для русской/казахской кириллицы не полагаться на ASCII `\b`. Словарь состоит из буквальных слов/фраз со стабильными ID; произвольные regex из файлов не исполнять.

Состояния: `clear` — совпадений по данной версии не найдено; `flagged` — есть совпадения; `not_checked` — словаря нет / проверка не выполнена. `clear` не равно «безопасно» и не равно «одобрено». Алгоритм не гарантирует поиск всех обфускаций, сленга и оскорблений.

`content/moderation-dictionary.json` из пакета пустой и не утверждён. Это честный placeholder, не рабочая защита от спама. Синтетический словарь для тестов лежит отдельно в fixtures, не попадает в production.

## Комплект выгрузки

В одном каталоге партии:

- `all.xlsx` — все записи: ID, дистанция, язык, имя, пожелание, телефон строкой, локальное время, UTC, ID устройства и словарная пометка.
- `10km.xlsx`, `21km.xlsx`, `42km.xlsx` — те же колонки, только нужная дистанция; пустой файл содержит заголовки.
- `moderation.xlsx` — только в расширении: один рабочий список без телефонов, статусы и заметки.
- `export-manifest.json` — batch ID, snapshot time, версия схемы/приложения, `device_id`, число записей всего и по дистанциям, SHA-256 файлов, статус complete.

Согласованный резервный `backup.sqlite` — отдельное действие менеджера; не путать его с XLSX, пригодным для чтения. Все файлы одной партии создаются с одного snapshot. Новая партия не перезаписывает прежнюю.

## Таблица модератора

Один лист «Пожелания», одна строка на ID. Поля: ID сообщения, дистанция, язык, имя и фамилия бегуна, пожелание, локальное время, автопроверка, версия словаря, статус, комментарий, ID партии. Телефонов нет.

По умолчанию все новые записи имеют статус «новое», в том числе готовые фразы. Человек читает имя и текст. В ячейке статуса есть список: «новое», «одобрено», «отклонено», «использовано». Столбцы ID и исходного текста не меняются при модерации; исправления смысла согласуются с организатором, а не делаются автоматически.

Одна назначенная рабочая копия — `moderation-master.xlsx`. Не рассылайте несколько редактируемых копий нескольким людям без отдельного процесса. Таблица работает в установленном офлайн-Excel; облачный Google Sheets не является обязательным шагом.

## Как сделать выборку в ролик без разработки админки

1. Сделать копию master на время подготовки.
2. Отфильтровать статус «одобрено» и дистанцию 10 км.
3. Скопировать **только видимые строки** ID / имя / пожелание / дистанция в новый файл как значения; не передавать весь отфильтрованный master со скрытыми отклонёнными строками.
4. Сохранить `approved-10km.xlsx`, повторить для 21 и 42 км.
5. Проверить состав на открытии без фильтров. Телефонов, отклонённых и новых строк нет.
6. Передать контент-команде. После фактического включения в ролик отметить соответствующие ID «использовано» в master.

Макросы, Power Query, динамические формулы FILTER и офисные аккаунты не нужны. Автоматическая генерация видео / синхронизация с LED не входит. В шаблоне `templates/moderation-template.xlsx` нет записей гостей и нет утверждённых материалов бренда.

## Повторная выгрузка / два дня / «объединение»

База не обнуляется ночью. Финальный snapshot содержит оба дня, поэтому для штатной одной панели объединять дневные файлы не нужно. Копии каждый час нужны для резервирования, а не для последовательного импорта всех строк в master.

Предпочтительный процесс: предварительные копии не размечать; после финального экспорта назначить один master. Если модерация началась раньше, старый master сохраняется; новые строки добавляет ответственный только по отсутствующим ID, не заменяя существующие статусы. Это ручной исключительный процесс, не обещанная функция автоматического объединения.

## Excel и пользовательский ввод

XLSX: всегда явно строковый тип для имени, текста, телефона и ID; не создавать формулы, гиперссылки или external links на основе ввода. Пример `=1+1` остаётся видимым текстом. Лимиты и Unicode сохраняются без обрезки данных.

CSV, если добавлен как fallback: UTF-8 BOM, корректное quoting, защита от интерпретации `= + - @`, начальных tab/CR/LF и обходов через ведущие пробелы. Защитный префикс применяется только к экспорту, не к данным в БД. Точный тест в используемом Excel обязателен; CSV не заменяет XLSX, обещанный клиенту.

## Персональные данные

Контактные XLSX и backup содержат телефоны; выдаются только назначенному организатором ответственному. PIN и наличие локальной БД не означают шифрование файлов. Проверить безопасный носитель, права пользователя ОС, порядок передачи, срок хранения и удаления. Не помещать реальные сообщения в Git, issue, LLM-контекст, screenshots или diagnostics.

Юридическое основание, уведомление, работа с именем третьего лица и дальнейшее использование телефона требуют утверждения организатором. В этом пакете они не заменены общим юридическим шаблоном.


## v2 Android: транспорт не меняет смысл таблиц

Комплект all/10/21/42/moderation/manifest теперь внутри одного ZIP. Native готовит
его локально и переносит через SAF, не через браузерную загрузку. Статус complete
в manifest означает проверенный внутренний комплект; результат внешней записи
подтверждается отдельно read-back/hash. Частично записанный документ не принимать.
Контактные XLSX содержат телефоны; весь ZIP передать менеджеру, модератору выдать
только moderation.xlsx. При передаче контент-команде — только новые файлы
одобренных строк без телефонов. SQLite backup — отдельный конфиденциальный ZIP.
