# План проверки и приёмки

**Статус приложения: все перечисленные ниже тесты NOT RUN.** Отдельный smoke-тест specs/schema.sql в validate_pack проверяет предложенную схему, не код приложения. Проверка структуры Excel-шаблона проверяет документ, не работу экспорта киоска.

## Модульные проверки · T01/T05

Для всех 9 сочетаний kk/ru/en × 10/21/42 обязательные поля проходят одинаковые правила. Пустой/пробельный ввод отклоняется; национальные буквы, Ё, апостроф и дефис не портятся. Границы длины измеряются согласованным способом, emoji не разрезаются. Телефон проверяется по выбранному формату, не по факту существования. Один номер может поддержать разных бегунов.

Готовая фраза подставляется и редактируется; повторный выбор не теряет ручной текст без предусмотренного подтверждения. Клавиатура работает с курсором и выделением, а не только дописывает в конец. Словарь не превращает clear в approved, пустой словарь → not_checked. Тестовый словарь не включается в production.

## Интеграция с SQLite · T00/T01/T03

Given новый валидный payload, When commit завершён, Then success и запись с тем же ID. Когда insert/commit fails, нет ложного подтверждения. Два запроса с одним ID и тем же payload возвращают одну запись; иной payload под тем же ID возвращает конфликт без перезаписи. Потеря ответа после commit + retry также даёт одну запись.

После завершения приложения и запуска все подтверждённые строки и device_id сохраняются. Второй экземпляр не открывает конкурирующий киоск. SQLITE_FULL/READONLY/BUSY и повреждённая тестовая копия дают безопасную ошибку; приложение не создаёт пустую замену. Проверки на копиях, не на рабочих данных.

## Экспорт и Excel · T04/T05

Проверить пустую БД и пустую отдельную дистанцию: файлы с заголовками, нет ошибки и выдуманных строк. Для непустой БД сумма трёх файлов равна all.xlsx и множества ID не пересекаются. Все файлы относятся к одному snapshot. Реальная generated-модерация содержит ID/тексты/статусы, но не телефоны. По умолчанию все статусы новое.

Проверить кириллицу/казахский, переносы, кавычки, пробелы, строки `=1+1`, `+SUM(1,1)`, `@test`: это текст, не формулы, не гиперссылки. ID и телефон — строковые ячейки. Проверить пользовательские строки с недопустимыми XML-кодами: валидация/безопасная нормализация без падения экспорта, документировать правило.

Файл с таким именем уже есть / диск полон / USB изъят: нет ложного подтверждения внешней записи, исходная база и прежняя копия целы. Локальный manifest может иметь complete ещё до открытия SAF; это не подтверждение копирования на USB. Повторное действие создаёт новый batch. Открыть generated-файлы в конкретном настольном Excel модератора. Отобрать approved по дистанции, скопировать только видимые строки как значения в новый файл; убедиться, что другие статусы/телефоны отсутствуют.

## Backup и восстановление · T03/T04

На тестовой базе создать закрытый согласованный snapshot через native pause/drain/close/copy/reopen, открыть копию отдельно, integrity_check и сверить ID/количество. Прерывание копирования не уничтожает предыдущую копию. Восстановить в отдельный каталог, запустить, экспортировать, сравнить. Не считать обычный XLSX полноценной резервной копией базы.

## UI / touch · T02/T06

Все четыре публичных экрана и состояния: ошибки валидации, loading, неизвестный результат отправки, отказ хранения, success, idle-warning, cancel. Во время отправки поля и повторный submit заблокированы. На следующей сессии не остаются имя/телефон/пожелание/язык/дистанция. Idle не сбрасывает активный ввод и не создаёт пустой записи.

Для всех локалей проверить клавиши и переносы, читаемость, касания, системную клавиатуру (нет наложения двух), работу без hover, видимый focus. Реальное разрешение и DPI подтвердить; 55″ не является достаточной спецификацией. Проверить досягаемость элементов на высоте установленной панели. Утверждённые KV/лого не искажены. Эмуляция portrait/landscape не означает поддержку двух форматов поставки.

## Холодный offline и packaged · T07/T08

На целевом вычислителе отключить сеть **до первого запуска установленной сборки**. Нет browser-cache предусловия, npm/Node/Python/dev-server, внешних шрифтов, CDN, Google Sheets, API и активации приложения. Пройти сценарий, перезагрузить ОС без сети, повторить сбор и экспорт. Проверить сетевые запросы в dev-инструментах/логах до закрытия debug-режима: внешние запросы не нужны для работы.

Проверить аварийное завершение процесса на синтетических данных. Аппаратный power-cut — только с согласия поставщика на тестовом наборе и при наличии копии. Сверить именно записи с полученным success. Этот тест не доказывает защиту от физической гибели диска; зафиксировать остаточный риск.

## Нагрузка и скорость

10 000 синтетических записей — технический запас, а не прогноз. Проверить загрузку, хранение, export и memory/latency. Предложенный soak: длительная тестовая сессия с последовательными отправками и периодическими backup; длительность зафиксировать по доступному времени панели. Не записывать «двухдневная проверка» без фактических двух дней.

Ручной замер минимум 10 прохождений предложен в PRD: отдельно свободное пожелание и фраза, от выбора языка до success. Записать наблюдаемое время и причины затруднений. Цель 20–30 секунд не заменять выдуманным результатом.

## Формат evidence

Для каждого случая: ID из AC, дата, версия приложения/схемы/ОС, устройство, шаги, ожидаемое, фактическое, PASS/FAIL/NOT RUN, безопасный скриншот/лог. Нет персональных данных. Критические FAIL по сохранению/экспорту/privacy закрываются до запуска; waiver не превращает FAIL в PASS.

Обратное чтение USB важно, но не отменяет безопасное извлечение и внешний backup.

## Уровни доказательств

PACKAGE: парсинг/схема/ассеты/HTML. BROWSER: Playwright/React. EMULATOR: Android API.
PANEL: устройство/USB/kiosk/touch/power. Не заменять PANEL результатами PACKAGE.
Для каждого теста хранить версию/дату/исполнителя/команду/ожидание/наблюдение и
ссылку на доказательство без реальных персональных данных.
